## 3. RULE BẮT BUỘC (giữ nguyên)
1. Không tin tên file/lời khẳng định: luôn trích dòng code, log, ảnh thật.
2. Toán N2/N4 phải tính và khóa TRƯỚC KHI CODE.
3. N4 <5%, đúng cơ chế thực: retry-tại-chỗ = Negative Binomial; không retry = Binomial; chọn-không-hoàn-lại = hypergeometric/permutation. Assert lựa chọn phân biệt NGỮ NGHĨA (kể cả near-duplicate) trên TOÀN BỘ nguồn dữ liệu thực, không chỉ nhánh fallback.
4. N2: margin dương trên worst-case content thật, tối thiểu +2.0s/round, nhắm ≥+3–4s (đo thật thường thấp hơn công thức 0.6–0.7s, có ca 2–3s). Quét toàn bộ tuần đã biên soạn + mọi fallback/default (đếm từ). Kiểm margin per-round lẫn cộng dồn so với T_avail. Số đo thật thắng công thức; không tự đánh "ĐẠT" khi số đo dưới sàn. Tốc độ đọc chuẩn: 0.67s/từ.
5. Tick hoàn thành cần đủ: (a) bảng N1–N5 kèm trích code thật, (b) validator khớp code thật, (c) 1 vòng chơi tay Phương án B + ảnh (waitForFunction đúng DOM state, không delay cố định).
6. Soi đồng đều mọi game, kể cả game "trông tốt".
7. `npm run build` exit 0 KHÔNG chứng minh logic đúng.
8. Test hook (teleport, window.__xxx) bọc `import.meta.env.DEV`; grep bundle production phải không thấy (exit code 1).
9. Đối chiếu ảnh ↔ JSON ↔ báo cáo (im lặng giữa 3 nguồn = dấu hiệu sai lệch). Sửa file dùng chung (HUDOverlay, contentService) phải verify non-regression trên ≥1 game khác.
10. Mọi số liệu tính tay (đếm từ, margin, xác suất) phải đối chiếu độc lập; không bỏ rơi mục treo từ vòng trước.
11. Thiết kế/sửa cơ chế mới: phản biện cơ chế TRƯỚC khi code. Đối chiếu 1–2 game thị trường cùng thể loại (nhịp độ, độ hấp dẫn), hỏi cơ chế có gắn chặt mục tiêu ngôn ngữ hay chỉ là lớp giải trí tách rời. KHÔNG sao chép rủi ro độc lập với ngôn ngữ.
