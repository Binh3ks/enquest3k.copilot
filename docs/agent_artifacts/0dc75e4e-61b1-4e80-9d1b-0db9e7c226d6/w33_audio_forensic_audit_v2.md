## SECTION 8 — PERMANENT AUDIO GENERATION DOCTRINE

> **This doctrine applies to ALL EngQuest3K W33+ audio generation. No exceptions.**

### RULE A — SOURCE OF TRUTH
Hub data (`listening_hub.js` etc.) is the ONE source of truth. All spoken text must be traceable to a hub field. Generation scripts transform data; they must NOT invent content.

**Required structures:**
```js
// Dialogue:
dialogue_script: [{ speaker: "woman", text: "Listen and write. There is one example." }]

// Instructions (L5):
instructions: [{ id: "inst_1", item: "Jake's Backpack", audio_text: "Colour Jake's backpack blue." }]

// L3 items (fix needed):
items: [{ id: 1, name: "School Stairs", target_letter: "A",
          audio_text: "What are the steps inside the school that go between floors? School stairs.", audio_url: "..." }]
```

### RULE B — SPEAKER IDENTITY IS METADATA
`speaker` field = metadata controlling voice selection.
`text` field = spoken content only.
`"Woman: ..."` in `text` is FORBIDDEN. The `tts()` safety guard enforces this.

### RULE C — MULTI-SPEAKER REQUIRES SEPARATE TTS CALLS
Cambridge L1, L2, L3, L4 require 2 speakers. Use separate TTS calls per turn:
```
man/boy  → en-US-Neural2-D
woman/girl → en-US-Journey-F
```
`validateDialogueScript()` must confirm ≥ 2 distinct voices when `required_speakers.length >= 2`.

### RULE D — ANSWER FIDELITY
Answer-bearing words (names, numbers, places, colours, times) must be verbatim or phonetically equivalent.
```
"2 minutes" → "two minutes"   ✅ acceptable normalization
"Nurse Sarah" → "Nurse Clara" ❌ factual error
"14" → "forty"                ❌ use spoken_text: "fourteen"
```

### RULE E — CEFR A2 FLYERS LANGUAGE LEVEL
Cambridge Listening audio: everyday A2 English, ≤15 words per sentence, age-appropriate.
CLIL/Explore audio: technical terms (friction, lubricant) acceptable when contextualised.
These are DIFFERENT standards for DIFFERENT station types.

### RULE F — EXAM MECHANICS FIDELITY
L4 specifically: answers MUST be distributed across A, B, C. All-A = invalid task.
L3 specifically: 8 cards (A–H), 5 scored items, 1 example = required counts.
Do not label a task "Cambridge L4" unless distractors are plausible and answers are distributed.

### RULE G — EXAMPLES REQUIRED
Every Cambridge part needs an example that demonstrates the mechanic without revealing a scored answer.

### RULE H — NO DUPLICATE PLAYS IN FILE
One clean recording per file. Player controls replay. Never concatenate dialogue twice.

### RULE I — NO SPOKEN UI ELEMENTS
FORBIDDEN to speak: "Question 1", "Man", "Woman", "Speaker 1", "Correct answer", "Answer key".
ALLOWED: Cambridge official exam instructions ("Listen and draw lines. There is one example.").

### RULE J — NO ANSWER LEAKAGE
L4 distractors must be plausible. Pattern recognition (all-A) = answer leakage. Invalid assessment.

### RULE K — NATURAL AUDIO QUALITY
```
Assessed content speaking rate: 0.85–0.90
Narrated content speaking rate: 0.90–1.00
Pauses between speaker turns: ≥ 200ms
```

### RULE L — ACRONYM / CAPITALIZATION
UPPERCASE in source ≠ spell-out. `"CARE"` → TTS receives `"care"`. Never "C-A-R-E" unless explicitly encoded as `spoken_text: "C-A-R-E"`.

### RULE M — TTS NORMALIZATION TRACKING
Digits, ordinals, abbreviations may be normalised. Verify answer semantics preserved. Add `spoken_text` field when normalization risk exists.

### RULE N — POST-PROCESSING INTEGRITY
Concatenation must: preserve turn order, insert ≥200ms silence on speaker switch, not clip words, not duplicate turns.

### RULE O — RUNTIME INTEGRITY
After generation: MD5-compare `public/audio/weekNN/` vs `dist/audio/weekNN/`. Vite does NOT auto-sync. Copy explicitly if mismatch. Run Whisper ASR on all modified files.
