# Repository Map — top-level inventory

Every visible top-level item in the repo, with its purpose, ownership, and a recommendation for the next agent: when to read, and whether to recurse.

Use this as the *table of contents* for the repo. Open the linked file (`../architecture/INDEX.md`, `../architecture/PROJECT.md`, `../architecture/ARCHITECTURE.md`) for the *why*. Use this file for the *where*.

## How to read this table

| Column | Meaning |
|---|---|
| **Path** | Where it lives in the repo (relative to repo root) |
| **Purpose** | One-sentence job description |
| **Owner** | Who is responsible for keeping it correct |
| **Read priority** | When an agent should open it (P0 = always, P3 = rarely / on-demand) |
| **Recurse** | Whether an agent should `find` / `ls -R` into it. `no` is a hint that recursive reads will burn context without payoff. |

## What an agent should NOT recurse into

The following are intentionally large, generated, or cache. Recursing them burns context and yields nothing:

- `node_modules/`
- `dist/`, `dist-ssr/`
- `public/audio/`, `public/images/`, `public/avatars/`
- `production_kit/data/cache/`, `production_kit/data/__pycache__/`
- `production_kit/tools/__pycache__/`
- `tools/` (use name search, not tree)
- `.wrangler/`, `.tmp/`, `.DS_Store`

These are listed in `.claudeignore` for exactly this reason.

## What an agent SHOULD recurse into (with intent)

- `.ai/architecture/` — to find the right architecture doc.
- `production_kit/tools/`, `production_kit/workflow/`, `production_kit/never_rules/`, `production_kit/reference/` — but read by file, not by tree.
- `src/modules/<one>/` — only the one you are touching. The subsystem is bounded.
- `src/data/weeks/week_NN/` — only the week you are producing.
- `tests/e2e/` — only when adding E2E coverage.

## Recursive-inspection policy

Default: **do not recurse.** Open the file you have a reason to open. Use `find … -maxdepth 1` or directory listings for orientation, not for content discovery. The cost of an unneeded recursive read is real (context burn), and there is no upside once you already know the layout from this map and from `SUBSYSTEMS.md`.
